# Region E: 0x7001400000 to 0x70017fffff (module main)

Scope: 17,451 functions in 16 windows of 256 KB each, read from the local index (`work/map/index/`). Tags: [C] confirmed by a string, SDK symbol or direct structure; [I] inferred from a strong pattern; [H] guess.

## Summary

This 4 MB range is mostly the game's own code, with one large standard library in the middle. Reading upward in address order: from about 0x7001400000 to 0x7001480000 is animation and the engine's base object layer; from 0x7001480000 to 0x7001548000 are game objects (ball, bat, stadium) and the studio's online-services client; from about 0x7001548000 to 0x7001648000 is OpenSSL (a standard encryption and secure-connection library, compiled in); and from about 0x7001650000 to 0x70017fffff is the game's own content layer: character creation, equipment and uniform assets, presentation and commentary text, and player and season records. The boundaries come from where the string families change, not from any file layout, so they are approximate to within a few 16 KB blocks. The last window (0x70017c0000) holds 4,710 functions, but 93% of them are tiny C++ class boilerplate, so function counts there say little about how many features the game has.

## The two huge windows

Only 0x7001780000 and 0x70017c0000 are inside this region. Together they hold 5,611 functions (901 + 4,710). Note that 0x7001780000 is not huge; the size is concentrated in 0x70017c0000.

### 0x7001780000 window (901 functions): presentation and commentary

This part has real strings. Presentation (scene) playback logs "pres id" errors, streams presentation data, and plays transitions such as "Transitions\\TransFlash". The commentary generator is around 0x70017b2978 to 0x70017b65b4: each function formats a short sentence from a template with "%s %s %s%s" plus phrases such as "throws to" and "is hit by the pitch". [C] for the strings, [I] that this is the game's broadcast text generator.

### 0x70017c0000 window (4,710 functions): mostly class boilerplate

Measured from the index (not by reading the code):

- 4,390 functions (93%) are 18 lines or fewer in the generated C. 2,127 are exactly 5 lines, 755 exactly 11 lines, 689 exactly 18 lines. Only 111 are 100 lines or longer, and 11 are 500 lines or longer.
- 4,159 functions (88%) are members of a virtual-method table (a vtable). A vtable is the list of function pointers a C++ class uses for its virtual methods, so being in one means the function is called through an object, not by a direct address.
- Calls made by these functions: 2,281 call nothing; 1,364 only call `operator delete` (the C++ memory-free function at 0x70005b19d0); 682 call `operator new` (the memory-allocate function at 0x70005b30a0); 383 make other calls.

Three example bodies, all read from `work/gen/main/main_0167.c`:

- f_70017d71b0 (9 lines): reads a pointer stored at offset 8 of its object, reads a 32-bit value through it, and returns its lowest bit. This is a one-line getter. It is in vtable 0x700223a550 at slot 6 of 7. [I]
- f_70017d71c4 (about 20 lines): allocates 16 bytes with `operator new`, stores two pointers into it (a vtable address 0x700223a598 and a second value), and returns the new object. This is an object factory or copy. [I]
- f_70017d71ac (5 lines): tail-calls `operator delete`. This is a deleting destructor: it frees the object's memory when it is destroyed. [I]

What this means: these are many small C++ classes with virtual methods (getters, factories, destructors) that the game's class system generates from templates. The studio's source includes template macros named "DEFINE_CLASSLABEL" and "YourClassName" in the neighbouring window 0x7001480000 [C], which fits this pattern. [I] The index cannot say which class each small method belongs to: the game has no symbol names and no runtime type records, so the classes are unnamed.

The larger functions in this window do have readable strings, and they are the game's own data records:

- Player profile and appearance: "D_PLAYER_ACC", "D_PLR_PROFILE", "PACKED_U32", "ACCESSORY_COLORS", "FACE_HAIR_STYLE", "NAME_STYLE", "NUMBER_STYLE" [C strings]. A face loader reports "GetFaceAppearanceFromSerialized_FROMJSON : ERROR" from f_70017c690c (5,057 lines) and f_70017c6740 [C]; this reads player appearance from JSON [I].
- Season and game records: "GAME_DATA", "D_SINGLE_G_DATA", "m_singleGameData", "D_PLAYOFF_ROUND", "LOSING_PIT", "WINNING_PIT", "AT_BATS", "STAT_VAL", "FIRST_NAME", "LAST_NAME" [C strings]. These are save and roster data, [I].
- A table walker: f_70017c1d20 (127 lines) loops over a table of 32-byte records, reading 16-bit and 32-bit fields, and calls two helpers, 0x70017c1ee0 and 0x7001c1fb40. Its string is "s9Amp", which occurs in 27 functions across the window. [H] for what "s9Amp" means; the function's purpose is not confirmed.
- Scouting and interest: "INTEREST_LEVEL", "SCOUTED_VALUE" in f_70017da880 [C strings, [I] scouting logic].

## Unknown / not examined

- Not checked: the window 0x7001800000 and above (outside this region). The string "Frontend" and "SubstitutionLogic", which the brief listed here, do not occur in this range.
- The vtable-to-class link: the index does not give class names, so the 4,159 vtable members in 0x70017c0000 are unnamed. Which game feature each class serves is unknown [H].
- Window 0x70014c0000 (1,542 functions, 1,081 vtable members): few strings, role unknown [H].
- The meaning of "s9Amp" and "S_CONTACT_HUM" / "S_CONTACT_CPU" (f_70017c19d0) is unknown [H].
- The OpenSSL boundaries are approximate: the first and last string hits were used, and the end at about 0x7001648000 is inferred from where the OpenSSL strings thin out.
- Generated C was read for only a few functions (f_70017d71ac, f_70017d71b0, f_70017d71c4, f_70017c1d20). Callees of the online-client and animation functions were not traced.
- The index counts only direct calls. Calls through a vtable are invisible in `callers`, so "0 callers" for vtable methods means "not called directly", not "not used".
- No game was run; all claims come from the static index and generated code.
