# Report: the match-start freeze (msdf skip)

Status: fix written and measured on two stadiums (branch `research/msdf-skip`, not merged). Default on, with a
settings row. More stadiums, times of day, weather, a whole match and game 1.0.15 are not checked yet; see "Not
proven".

> **For a player.** When a match starts, the game freezes for a moment while it draws a map of the field's edges.
> That step took about 0.69 second. With this fix it takes about 0.19 second, so the freeze is about half a second
> shorter. The field looks the same: on the two stadiums we tested, the finished picture is identical to the last byte.
> The setting is "Shorter freeze at match start" in the Game tab of the settings menu. It is on by default and
> applies after a restart.

All numbers are from one machine (RX 6700 XT, i5-12400F), game 1.0.20.

## Cause

At match start the game builds a 512x512 "distance picture" of the field's edges (the msdfgen step). Each pixel says
how far it is from the nearest edge. It then runs an error-correction pass over the picture, looking for pixels where
the distances look wrong.

Most of the picture is empty space far from any edge. Measured before the pass starts:

- 97.1 % of the pixels hold plus or minus infinity in all three channels (61.5 % minus infinity, 35.7 % plus
  infinity). Infinity here only means "inside" or "outside", with no distance.
- Only 2.9 % (7,506 pixels) hold real distances.

The pass (`f_7000030ec0`, that is main+0x30ec0, with `f_7000031e70`, `f_7000033530`, `f_70000339a0`, `f_70000336bc`)
visits every pixel, including the empty ones. For each pair of neighbours it computes `t = (a - 0.5) / (a - b)`. When
the input is infinite this is not a number (a NaN, "not a number": the result of a sum with no answer, such as
infinity minus infinity). A NaN fails the "there is an edge between these pixels" test, so the answer for every
infinite pixel is "no artefact". The game spends most of the step proving that empty space has no edges.

Counts per match start: about 67 to 70 million NaN results. About 18.4 million are born as float `inf - inf`; the rest
are those NaNs carried on through later multiplies, divides and fused multiply-adds. The NaNs are the game's own, not
a port bug: the input really is infinite.

## The fix

A code patch set, `msdf_skip`, in `tools/data/patches-1.0.20.txt`. It is switched by `MLB_MSDF_SKIP` (default on) and
has a settings-menu row, "Shorter freeze at match start" (`runtime/mlb/cfg.c`, `runtime/gfx/ui/menu.cpp`).

At main+0x311a0 the pass already skips a pixel that is flagged. The patch makes it also skip a pixel whose three
channels are all plus or minus infinity. It is 19 instructions that read the three channels, clear the sign bit, xor
in 0x7f800000 (zero exactly for infinity) and branch back to the skip when the result is zero. It uses only free
registers (x10 to x13), and the flag byte is read again from memory later, so nothing else in the pass changes.

## What else changes

- Grass step: unchanged, about 155 ms with the skip off and on.
- The float fix-up (`research/float-fixup`) made each NaN cheaper (step 702 to 525 ms). Once the NaNs are gone it
  matters much less. It needs measuring again before it is merged.
- With the setting off (`MLB_MSDF_SKIP=0`) the game runs its original pass.

## How it was checked

Timing: six runs of 35 s, off and on alternated. MSDF step in ms:

| Skip | Run 1 | Run 2 | Run 3 | Mean |
| --- | --- | --- | --- | --- |
| off | 683 | 706 | 673 | 687 |
| on | 166 | 221 | 182 | 189 |

A later single pair gave 888 ms off and 206 ms on (noisy, so only a rough check).

Output: the finished 512x512 field texture (format 0x25, 1,048,576 bytes) is byte for byte identical with the skip
off and on. Same SHA-256 (prefix 7a11da1b54bb16d3), byte sum 147739026, 587113 non-zero bytes. The owner also looked
at the field in game and it looked right. A byte compare is the real test; the eye check adds nothing a number does
not already show.

### Second stadium: Baltimore (BAL home, BOS away), 2026-11-23

The dev harness wrote the dump this time (scenario `tools/scenarios/bal-tor-field.txt`, key
`dump = texture:fmt=0x25,size=512x512`), so no temporary dump code was needed. The exe was `main` at 8f1209c merged
into `research/msdf-skip` (14c66c9). Four runs of 40 s, off and on alternated, one game on the machine at a time:

| Skip | Run | MSDF step (ms) | Field picture |
| --- | --- | --- | --- |
| off | 1 | 723 | 1,048,576 bytes |
| on | 2 | 187 | 1,048,576 bytes |
| off | 3 | 727 | 1,048,576 bytes |
| on | 4 | 186 | 1,048,576 bytes |

Byte compare: 0 of 1,048,576 bytes differ, off against on (run 1 against run 2), and on the repeats (1 against 3, 2
against 4). All four have SHA-256 5f450eca81b533dcc436c911e5fb081f35641ccc7170588480f6d55a3bc4e6a0, byte sum
127082744 and 506424 non-zero bytes: a different picture from Dodger Stadium's, so the team override took effect. Each
run's log shows the state it ran with (`patches: ... msdf_skip off` or `on`), one 512x512 write, and the `MSDF took`
line before that write. Mean of two runs each: 725 ms off, 187 ms on.

One timing note: the first run in the newly copied game folder took 37.1 s to reach the field picture; the next three
took 22.5 s. The MSDF step itself did not change (723 against 727 ms).

## Not proven

- Two stadiums only: Dodger Stadium (LAD home, TOR away) and Baltimore (BAL home, BOS away), each at the default time
  of day and weather.
- Reading the guest code showed the pass marks a pixel only through two classifier calls (`f_70000336bc`,
  `f_7000033530`). The divide-based range tests give NaN for an infinite pixel whatever its neighbours hold, so for
  those the skip cannot change the answer. But a range test can pass for an infinite pixel, and `f_70000336bc` then
  checks the real stadium outline. What that call does for infinite pixels cannot be worked out offline. So the
  identical output is shown for two stadiums, not proven for all.

Open items: more stadiums, times of day, weather, a whole-match run, and game 1.0.15 (its address needs the 1.0.15
exefs for `tools/addrmap.py`, which is not on this machine).

How to repeat the byte check: with a dev build that has both the harness and this branch (`main` merged into
`research/msdf-skip`), run the scenario once with `MLB_MSDF_SKIP=0` and once with `MLB_MSDF_SKIP=1`, each with
`MLB_HARNESS=<the scenario file>` and an `MLB_HARNESS_OUT` folder of its own, then run `python -I tools/harness.py
compare <run A> <run B>` on the two folders that hold those `dumps` folders.
